## Подтверждённые ограничения и рекомендации

1. **Высокий приоритет — форма консультации не отправляет заявку.** После заполнения она выводит локальное сообщение с предложением позвонить или написать в Telegram (`app/ui/interactive.jsx`). Для настоящего приёма заявок нужны согласованный получатель, серверная отправка, валидация и обработка персональных данных. До подключения сервиса следует убрать обещание отправки из интерфейса или вести посетителя напрямую в действующий канал связи.
2. **Средний приоритет — очень крупный исходник истории.** `public/assets/enhanced/history.webp` занимает 9,95 МиБ. Вариант `next/image` шириной 3840 при качестве 90 отдаёт 2,28 МиБ; качество 75 в том же размере дало 1,34 МиБ. Стоит проверить качество на целевых экранах и уменьшить `quality` для изображений ниже первого экрана либо подготовить исходник меньшего размера.
3. **Средний приоритет — кэширование файлов в `public/`.** Локальный сервер выдаёт новым WebP `Cache-Control: public, max-age=0`; браузер будет повторно проверять их актуальность. Для длительного кэширования нужны имена с версией или хешем и соответствующие заголовки в конфигурации хостинга.
4. **Средний приоритет — редактор загружается всем посетителям.** `EditorProvider` обходит около 620 элементов и подключается на главной странице для каждого пользователя. Если редактор нужен только команде, его стоит изолировать за отдельным режимом и загружать по запросу. Это требует решения о способе доступа к режиму редактирования.
5. **Перед публикацией — метаданные закрывают сайт от поиска.** В `app/layout.jsx` выставлено `robots: { index: false, follow: false }`. Для прототипа это уместно; при публичном запуске потребуется пересмотр.
6. **Низкий приоритет — последний ввод редактора может потеряться при мгновенном обновлении.** Черновик пишется в `localStorage` через 250 мс после изменения. Тесты ожидают фактической записи перед перезагрузкой. Для гарантии при закрытии вкладки можно добавить запись на `pagehide` или явное сохранение.

При проверке выявлено также локальное состояние, влияющее на диагностику: старый процесс `next start` остался запущенным после новой сборки и отдавал HTML со ссылкой на удалённый CSS (404). После остановки старого процесса и чистого запуска оба CSS-файла ответили 200. Для повторяемых замеров останавливайте все процессы `next start` перед пересборкой.

## Что осталось вне проверки

Не проверялись производственный хостинг, CDN, мобильная сеть, реальные Core Web Vitals, географическая задержка, длительная нагрузка и отправка заявок, поскольку серверной отправки нет. Для решения о готовности к публикации нужны staging-стенд и тест нагрузки в конфигурации будущего хостинга.
